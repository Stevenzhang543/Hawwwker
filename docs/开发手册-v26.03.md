## 0. 一页纸摘要

1. **换底座**：Python FastAPI + Edge `--app` 窗口 + 浏览器内 HTTP 登录 → Tauri 原生桌面应用。前后端走 IPC（`invoke` / `emit`），不再有本地 HTTP 端口、管理员密码、启动令牌、SSE 断线重连等一整类问题。
2. **登录态重做**：从"Cookie 存在即已登录"改为**状态机 + 结果验证**（搜索成功即刷新"已验证"，撞登录墙即标"已过期"）；登录窗口被用户关掉会立刻结束等待；"我已登录"手动确认；退出某平台只删除该平台 Cookie，不再"清空全部再写回"。
3. **搜索准确度**：规则解析 → **AI 规划**（按平台、按语言生成本地化搜索词）；卡片解析加入字号/字重线索；**AI 二次校验**每条结果与需求的匹配度（精确 / 接近 / 相关 / 不符），不符的默认收起；跨平台同款聚合。
4. **AI 必须接入**：首次启动的引导流程中必须完成 AI 连接测试才能进入主界面；所有搜索、监控命令在 Rust 侧再校验一次。
5. **国际化平台**：平台按"家族 → 版本"组织：小红书 ⇄ RedNote、抖音 ⇄ TikTok、拼多多 ⇄ Temu、京东 ⇄ Joybuy、淘宝 ⇄ AliExpress、1688 ⇄ Alibaba.com、Amazon .com/.de/.co.uk/.co.jp、eBay .com/.de 等，共 30+ 个入口；支持自定义平台。
6. **业务主线**：搜索（发现）→ 追踪（盯价/监控/提醒）→ 洞察（走势/市场分析）→ 跳转平台下单或联系商家。三种角色（消费者 / 商户 / 平台分析）共用一套能力，首页与 Copilot 技能按角色排序。
7. **界面**：无边框窗口 + Windows 11 Mica 系统级模糊 + 液态玻璃 + 动态模糊（滚动联动模糊、模糊入场、景深弹层）；一级导航分组 + 二级菜单 + 三级详情抽屉；命令面板、灵动岛通知、Live Activity 进度、弹簧动画、涟漪与按压反馈。
8. **Copilot**：全局侧栏助手（Ctrl+J），技能：礼物构思、比价顾问、行业判断、选品分析、入手时机、商品文案；回答里附"一键执行"动作（发起搜索、加入追踪、打开链接）。
9. **v26.02**：渐进式结果（每个平台搜完先出规则初判，AI 核对后原位更新）、**到手价**（运费 / 包邮 / 券后 / 满减）、**价格判断**（历史最低 / 近期低位 / 正常 / 偏高）、粘贴商品链接找同款、"不相关"反馈、复制清单 / 导出 CSV、提醒"去购买"、商户"我的售价"、本机模型检测、按地区推荐平台、平台自检；侧栏精简为 5 个一级入口 + 顶部标签页；CDP 改为管道通信；提供 Windows 安装包与便携版。

## 1. 现状评估（v3.4 代码阅读结论）

### 1.1 结构

```
source/
├── desktop.py            Tk 控制窗 + uvicorn 线程 + Edge --app 窗口
├── app/main.py           FastAPI 工厂、启动令牌、后台监控循环
├── app/agent/            planner.py（规则解析 512 行）、llm.py（OpenAI 兼容，可选）
├── app/browser/          manager.py（CDP 客户端）、search.py（平台规则、卡片解析、登录发现）
├── app/connectors/       淘宝联盟 / 多多进宝签名 API；抖音/小红书/视频号骨架；JSON/RSS/Webhook
├── app/services/         search 编排、ingestion 入库、scoring 线索分、copywriter 文案、monitor、notify、insights、export
├── app/nlp/              词典、分词、情感、意图
└── app/web/              原生 JS 单页（915 行 app.js）+ 液态玻璃 CSS
```

数据流：指令 → 规则计划（可选 LLM 合并）→ 各连接器并发（API 或浏览器 CDP）→ 过滤/逐级放宽 → 跨平台去重 → 入库 → 线索评分 → 文案 → SSE 推送前端。

### 1.2 做得好的、v26.01 保留的设计

- 不依赖 Playwright，直接用 CDP 驱动本机 Edge/Chrome，独立用户目录保存登录态（体积小、真实浏览器）。
- 登录页不注入脚本，由用户本人在官网完成登录；Cookie 内容不显示、不导出、不上传。
- 站点级节奏控制（同站两次打开间隔 ≥3 秒）、自适应滚动、卡片"无链接"兜底识别、跨行价格解析。
- 可解释的过滤统计（每类被过滤多少条）、监控只通知"首次出现"。

### 1.3 问题清单（按严重度）

| # | 级别 | 位置 | 问题与根因 | v26.01 处理 |
|---|---|---|---|---|
| L1 | 致命 | browser/search.py `start_login` | 用户关闭登录窗口后，后台仍按"等待中"轮询 10 分钟；期间再次点「登录」直接返回旧状态，**窗口不再打开** → 登录"卡死" | 浏览器级连接订阅 `Target.targetDestroyed`，窗口关闭立即结束流程（若检测到已登录则判成功，否则"已取消"）；任何状态都可重新发起 |
| L2 | 高 | `_fingerprint` | 以"登录 Cookie 值变化"判定登录完成；抖音 `sid_guard`、淘宝 `cookie17` 等在打开首页时就会刷新，小红书 `web_session` 游客也有 → **还没登录就判定成功并关窗**，或游客被显示为"已登录" | 每个平台区分"游客 Cookie"与"账号 Cookie"；变化需连续两次轮询稳定且登录页已跳走；提供「我已登录」手动确认 + 「验证」按钮 |

## 2. 产品定位与工作流

### 2.1 一句话定位

**你只说要什么，Hawwwker 在你登录好的各个平台上替你搜、替你比、替你盯，最后把你带回平台下单或找商家。**

所有操作发生在用户自己的电脑和自己的登录会话里，速度接近真人、窗口随时可见，用户可以暂停、取消；登录、验证码由用户本人完成。

### 2.2 三种角色

| 角色 | 典型问题 | 首页 | 核心闭环 |
|---|---|---|---|
| 消费者 | "德国哪里买 Switch 2 最便宜？""给 30 岁程序员男友送什么？" | 智能搜索 | 配置平台 → 搜索/盯价 → 应用内跳转平台或联系商家 → 下单 |
| 商户 | "我的蓝牙耳机定价在市场处于什么位置？竞品降价了吗？" | 价格追踪 | 配置平台 → 盯竞品/盯品类 → 价格带与走势 → 调价/选品决策 |
| 平台分析 | "这个品类在各平台的价格分布与趋势如何？" | 市场分析 | 配置平台 → 定时监控品类 → 趋势与分布 → AI 分析报告 |

角色只影响默认首页、示例指令、Copilot 技能排序与分析页默认视图，**不限制功能**；可随时在侧栏顶部切换。

### 2.3 统一工作流

```
① 配置  平台目录（国内版/国际版）→ 账号与登录（一次登录，长期复用）→ AI 模型（必选）
② 发现  一句话 → AI 规划（本地化搜索词/预算/币种/排除）→ 多平台并行 → 抽取 → AI 校验 → 同款聚合 → AI 总结
③ 决策  结果卡片（换算价、匹配理由、也在…平台）→ 详情抽屉（历史价格、同款比价）
④ 追踪  单品盯价（目标价提醒）/ 定时监控（保存的搜索，新品与最低价提醒）
⑤ 洞察  价格走势、平台价差、价格带、AI 分析报告
⑥ 行动  在系统浏览器打开商品页/店铺页 → 用户自己完成下单或联系商家
```

### 2.4 关键用例（验收用）

1. 首次启动 → 引导：选角色 → 填 AI（测试通过才可继续）→ 选地区与平台 → 进入首页。
2. 输入"帮我在亚马逊德国和 eBay 找 Sony WH-1000XM5，200 欧以内，不要二手" → 计划显示：Amazon.de 搜 `Sony WH-1000XM5`、eBay.de 搜 `Sony WH-1000XM5 neu`、上限 200 EUR、排除 二手/gebraucht/refurbished → 结果按换算价排序，配件被标为"不符"并折叠。
3. 某平台未登录 → 该平台标"需要登录"，不打断其他平台；点"去登录"→ 官网窗口出现 → 用户关闭窗口 → 状态立刻变为"已取消"，可再次发起。
4. 在结果上点"追踪"并设目标价 → 追踪页出现 → 调度器按间隔打开商品页读价 → 低于目标价 → 系统通知 + 应用内提醒 + （可选）群机器人。
5. 打开 Copilot："给喜欢露营的爸爸挑 500 元以内的礼物" → 输出 3 个方向 + 每个方向一个"去搜索"按钮 → 点击即发起搜索。

## 3. 信息架构与界面

### 3.1 层级

v26.02 起：侧栏只放 5 个一级入口（搜索 · 追踪 · 洞察 · 平台 · 设置）+ Copilot；二级页面显示为顶栏左侧的标签页（`PageTabs`，数据来自 `src/nav.ts`），点一级入口回到该组上次停留的标签。路由地址不变。

```
一级（侧栏入口）     二级（顶部标签页）          三级（抽屉 / 弹层）
搜索 Search     ─ 智能搜索 /discover/search    ─ 商品详情抽屉、计划编辑、链接卡片
                └ 搜索记录 /discover/history   ─ 历史运行回放
追踪 Track      ─ 价格追踪 /track/watchlist    ─ 追踪详情（走势、目标价）
                ├ 定时监控 /track/monitors     ─ 监控编辑
                └ 提醒中心 /track/alerts
洞察 Insights   ─ 价格走势 /insights/trends
                └ 市场分析 /insights/market    ─ AI 报告
平台 Platforms  ─ 账号与登录 /platforms/accounts ─ 登录进度浮层
                └ 平台目录（高级）/platforms/catalog ─ 自定义平台、平台检测、编辑模板
设置 Settings   ─ AI 模型 /settings/ai
                ├ 通用 /settings/general
                ├ 通知 /settings/notify
                └ 数据 /settings/data
全局            Copilot 侧栏（Ctrl+J）· 命令面板（Ctrl+K）· 灵动岛通知 · 引导 /onboarding
```

侧栏：5 个入口带角标（运行中、未读、待处理登录）；窄窗口（<1100px）自动收为图标栏。顶栏：一级名称 + 二级标签页、全局搜索框（打开命令面板）、运行中指示、通知铃（最近 5 条 + 查看全部）、主题切换。

### 3.2 视觉语言

- **窗口**：无系统边框（自绘标题栏，`data-tauri-drag-region`），透明窗口 + Windows 11 **Mica** 效果（Win10 退化为 Acrylic，不支持时纯色），应用背景是缓慢流动的极光渐变 + 细颗粒噪点。
- **材质**：液态玻璃三层（`--glass-1` 卡片 / `--glass-2` 浮层 / `--glass-3` 模态），`backdrop-filter: blur() saturate()`，1px 高光描边 + 内阴影；指针跟随镜面高光（CSS 变量 `--mx/--my`）。
- **动态模糊**：
  - 滚动联动：内容区滚动距离映射到顶栏 `blur(8→28px)` 与不透明度；
  - 模糊入场：页面与卡片以 `opacity 0 → 1 + translateY(8px) + blur(10px → 0)` 进入，离场反向；
  - 景深：打开抽屉/命令面板时，背景层 `scale(.985) + blur(6px)`；
  - 运动模糊：灵动岛展开/收起、Live Activity 进度条推进时加短暂方向性模糊。
- **色彩**：品牌渐变 鹰蓝 `#3D7BFF` → 紫 `#8A5CFF`；"鹰眼"琥珀 `#FFB020` 只用于价格与好价提醒；成功 `#2FD27A`、警示 `#FF9F0A`、错误 `#FF4D4F`。深浅色两套 token，跟随系统。

### 3.3 关键页面规格

**智能搜索（核心页）**
- 首屏：大号玻璃指令框（自动增高，Ctrl+Enter 运行），左侧 AI 徽标，右侧"运行"磁吸按钮；下方一行：地区分段（全部 / 国内版 / 国际版）+ 已选平台芯片（点开平台选择浮层）+ 结果数量；再下方是按角色的示例指令卡片。

- 计划卡：AI 生成的计划以芯片展示（目标、品类/品牌/型号、预算+币种、排除、各平台搜索词），可展开编辑后"按此计划重新搜索"。

## 4. AI 辅助体系

### 4.1 必须接入

- 引导第 3 步必须"测试连接"通过（返回非空回答）才可继续；之后若 AI 被清空或连续失败，路由守卫把用户带到 `/settings/ai`，顶部横幅说明原因。
- Rust 侧所有 `search_*`、`monitor_run`、`watch_check`（需 AI 兜底时）、`copilot_*`、`insights_report` 先检查 `ai.configured`，否则返回错误码 `AI_REQUIRED`。

### 4.2 模型与协议

| 字段 | 说明 |
|---|---|
| protocol | `openai`（`/chat/completions`，DeepSeek/Qwen/Kimi/GLM/OpenAI/Gemini 兼容端点/Ollama）或 `anthropic`（`/v1/messages`） |
| baseUrl / apiKey / model | 主模型：规划、总结、Copilot、报告 |
| fastModel | 可选，快速模型：卡片抽取、相关性校验（大批量、低成本）；为空则用主模型 |
| temperature / timeoutSecs | 默认 0.2 / 60s |

预设模型（v26.03，2026-11-02 按官方文档核实；界面"获取模型列表"以服务商 `GET /models` 为准）：DeepSeek `deepseek-flash` / `deepseek-v4-pro`（`deepseek-chat`、`deepseek-reasoner` 已于 2026-07-24 停用，官方地址上的旧配置自动迁移）；通义 `qwen3.8-max` / `qwen3.7-plus` / `qwen3.8-flash`；Kimi `kimi-k3.1-pro` / `kimi-k3` / `kimi-k3.1-pro-highspeed`；智谱 `glm-5.3` / `glm-5.2` / `glm-4.7-flash`；OpenAI `gpt-6.1-sol` / `gpt-6-astra` / `gpt-6.1-terra` / `gpt-6-luna`；Anthropic `claude-sonnet-5-5` / `claude-opus-5-5` / `claude-haiku-5-5`；Gemini `gemini-3.8-flash` / `gemini-4-argon` / `gemini-3.5-flash-lite`；Ollama `qwen3.5:9b` / `qwen3.8:27b` / `qwen3.5:4b`。DeepSeek（`thinking: disabled`）、通义（`enable_thinking: false`）、智谱在结构化调用中关闭思考模式，服务商拒绝该参数时自动去参重试；响应兼容 `reasoning_content` 与 Anthropic thinking 块。

JSON 输出容错：去除代码围栏 → 截取第一个完整 `{…}` / `[…]` → serde 校验 → 失败重试一次（附带错误信息）→ 仍失败按阶段降级。

### 4.3 搜索链路中的 AI（5 个调用点）

| 阶段 | 模型 | 输入 | 输出（JSON） | 失败降级 |
|---|---|---|---|---|
| ① 规划 plan | 主 | 指令 + 可用平台清单（id/名称/地区/语言/币种）+ 角色 + 显示币种 + 规则预解析的数字 | `SearchPlan`：goal、product{category,brand,model,attributes,mustHave,mustNot}、keywords、exclude、priceMin/Max + currency、condition、platforms、**queries[{platformId,q,lang}]**、sort、limit、monitor、notes | 规则计划（数字由规则解析，关键词取剩余文本）并提示 |
| ② 抽取 extract | 快 | 规则解析失败或低置信的卡片文本（每批 ≤25 条，每条 ≤500 字） | `[{i,title,price,currency,sales,rating,shop,condition}]` | 保留规则结果 |
| ③ 校验 verify | 快 | 结构化需求 + 候选（i、平台、标题、价格、店铺、成色）每批 ≤30 | `[{i,score 0-100,verdict:exact|close|related|mismatch,reasons[],flags[],productKey}]` | 用关键词覆盖率给分，标记"AI 未校验" |
| ④ 聚合 cluster | — | `productKey` + 标题相似度（bigram Jaccard ≥0.8） | `clusterId`，同款显示"也在…" | 仅标题相似度 |
| ⑤ 总结 summarize | 主 | 计划 + 前 20 条（换算价、匹配、平台）+ 价格统计 | `AiSummary`：headline、bestPick{id,why}、bullets、priceInsight、caveats、nextActions | 不显示总结卡 |

**准确度要点**
- 规划阶段为每个平台生成**本地语言**搜索词（Amazon.de 用德语/型号、RedNote 用英文、淘宝用中文），并保留型号原文。
- 校验阶段明确告诉模型："配件、套装、二手/翻新、仅外观相似、不同代际/型号" 属于 `mismatch` 或 `related`，并要求给出理由。
- 不符结果不直接删除，而是折叠到"可能不相关"，避免误杀（v3.3.1 的教训）。
- 校验结果按 `(计划指纹, 商品内容哈希)` 缓存 7 天，重复搜索不重复花钱。

### 4.4 其他 AI 能力

- **商品页读价兜底**（追踪）：JSON-LD / meta / 最大字号价格都失败时，把主体文本前 3000 字交给快速模型抽取 `{price,currency,available}`。
- **市场分析报告**：输入统计摘要（不含原始个人信息），流式输出 Markdown 报告。
- **Copilot**：见 4.5。

### 4.5 Copilot

- 入口：侧栏底部按钮 / Ctrl+J / 结果卡"问 Copilot"（携带该商品上下文）。
- 技能（按角色排序）：🎁 礼物构思、⚖️ 比价顾问、🧭 行业判断、📦 选品分析、⏱ 入手时机、✍️ 商品文案（商户）。
- 上下文：当前页面（搜索结果前 10 条、选中商品、追踪列表摘要）由前端打包为精简 JSON 传入。
- 动作协议：回答末尾可附加 ```` ```actions [...] ``` ```` 代码块，Rust 解析为 `CopilotAction[]`（`search` / `watch` / `open` / `navigate`），前端渲染为按钮；动作必须用户点击才执行。
- 流式：`copilot://delta` 逐段推送，`copilot://done` 返回完整消息；会话存 SQLite，可清空。

### 4.6 成本与隐私

- 只把商品公开信息与用户指令发给模型；不发送 Cookie、账号信息、个人作者昵称（作者字段一律脱敏或不采集）。
- 用量表 `ai_usage` 按天统计调用次数与 token；设置页可见。
- 并发上限（默认 3）防止突发计费。

### 5.5 安全

- `capabilities/default.json` 只授予主窗口所需权限（窗口控制、事件、opener 打开 http/https 外链、通知）。
- CSP：`default-src 'self'; img-src 'self' https: data: blob:; style-src 'self' 'unsafe-inline'; connect-src ipc: http://ipc.localhost`。商品图片来自 https 外链，只用于 `<img>`。
- API Key 存 `secrets` 表，不出 Rust；日志脱敏。
- 自动化浏览器默认用 `--remote-debugging-pipe`（fd 3 写入 / fd 4 读出，`\0` 分隔 JSON），**不开放任何端口**；Windows 通过 `CreateProcessW` 的 `lpReserved2` CRT 句柄表传递管道，Linux 用 `dup2`。管道启动失败时才回退到 127.0.0.1 随机端口（`--remote-allow-origins` 仅限 `http://127.0.0.1`），界面显示当前模式。
- 子进程生命周期：Windows Job Object（`KILL_ON_JOB_CLOSE`）、Linux `PR_SET_PDEATHSIG`，主程序退出（包括被强制结束）时浏览器一并退出。

### 6.3 登录状态机

```
状态 status：unknown → logged_out | logged_in | expired | not_needed
流程 flow：idle → opening → waiting（用户在窗口中登录）→ verifying → success | cancelled | timeout | failed

判定：
  logged_in  = 有账号 Cookie 且 (last_wall_at 为空 或 verified_at > last_wall_at)
  expired    = 有账号 Cookie 但最近一次搜索撞到登录墙（last_wall_at > verified_at）
  logged_out = 没有账号 Cookie
完成登录检测（waiting 中每 2 秒）：
  账号 Cookie 新出现/变化 且 连续两次一致 且 标签页 URL 不再是登录页 → verifying → 持久化会话 → success → 窗口收回
  标签被关闭 → 立刻检查一次：有账号 Cookie → success，否则 cancelled
  用户点「我已登录」→ 立即进入 verifying
  10 分钟无结果 → timeout
任何时刻可 login_start 重新开始（旧流程被替换），login_cancel 关闭窗口并结束。
```

### 6.4 搜索页抽取

1. 打开搜索地址（站点节奏 ≥3 秒），等待 `readyState` 与首批结果；检测登录墙/验证（文字线索 + URL 线索）。
2. 链接模式：按 `linkPattern` 找结果链接 → 向上找卡片容器（遇到第二个结果链接或第二个价格簇即停）。
3. 卡片模式兜底：商品图（≥60px）+ 价格/销量文字的最小容器。
4. 每张卡片返回：`id, href, img, titleAttr, lines[{t, fs(字号), fw(字重), a(是否链接文字)}]`。
5. Rust 解析：标题 = 标题属性 > 链接文字中最长行 > 字号最大的长行；价格 = 字号最大的货币数字（跳过划线价 `line-through`、券/满减）；原价 = 划线价；销量/评分/评论数按语言词表。
6. 自适应滚动：数量够或连续两屏无新增即停（最多 6 屏，每屏 1.3–2.6 秒）。
7. 撞登录墙：已登录状态下（会话过期）若开启"搜索时允许弹窗"则显示窗口等用户处理；否则该平台标"需要登录"，不打断其他平台。

### 6.5 价格与币种

- 货币识别：`¥ ￥ 元 RMB CNY`（国内平台）/ `¥ 円 JPY`（日本站）/ `€ EUR` / `$ US$ USD` / `£ GBP` / `HK$` / `₩`。
- 数字格式：`de-DE`/`fr-FR` 使用 `.` 千分位、`,` 小数（`1.299,00`），其余 `,` 千分位；`1.2万`、`3k` 等中文/英文单位。
- 汇率：启动后从 ECB（frankfurter.app）拉取，失败自动改用 open.er-api.com（至少 10 种币种且含 CNY/USD 才采用），缓存 12 小时；都失败时用缓存或内置参考表。结果显示"原币价格 + 换算到显示币种"。
- **到手价**（v26.02）：卡片解析识别运费（`+4,99 € Versand`、`运费 8`、`送料`）、包邮 / Free shipping / Kostenloser Versand、券后价（`券后¥1799`）、满减（`满300减40`）、百分比券（`10 % Coupon`）；`landed = (券后价 ?? 标价) + 运费`；预算过滤与价格排序按到手价换算后比较。
- **价格判断**（v26.02，`deal.rs`）：取同一商品近 180 天同币种价格点；不足 3 个点或不足 2 天为"数据积累中"；否则 ≤ 最低价 × 1.005 为"历史最低"（≥30 天）/"近期最低"，≤ 25 分位为"近期低位"，≤ 中位 × 1.05 为"价格正常"，其余"偏高"；附依据文本。

## 7. 价格追踪与监控

| 能力 | 机制 |
|---|---|
| 价格历史 | 任何搜索看到的商品都记录价格点（同日同价合并），追踪项还会定时打开商品页读价 |
| 单品盯价 | `watches`：间隔默认 6 小时（最短 30 分钟）；读价优先级：JSON-LD Product.offers → meta 价格 → 最大字号货币数字 → AI 兜底 |
| 定时监控 | `monitors`：保存的搜索计划，按间隔重跑；对比上一轮：新出现的商品、最低价变化；低于目标价提醒 |
| 调度器 | 每 30 秒扫描到期任务，派发为独立任务（同一时刻最多 1 个监控 + 2 个读价），保活每 6 小时一次；启动时清理遗留 running |
| 提醒 | 应用内 notices + 系统通知 + 群机器人（企业微信/飞书/钉钉/Slack/Discord/通用 JSON） |

提醒规则：降价 ≥ 设定比例（默认 5%）、达到目标价、监控发现新品（且匹配度为精确/接近）、登录过期、连续 3 次读价失败。

| 问题 | 修复 |
|---|---|
| 取消/超时丢弃搜索 future 时标签页不关闭，窗口可能留在屏幕上 | `TabGuard`：future 被丢弃时自动关闭标签并从可见集合移除 |

### 11.4 已知限制与后续

- **Windows 安装包需在本机生成**：开发环境无法下载 Windows 目标的 Rust 标准库，已提供 `scripts\build.bat`（首次约 5–10 分钟）。→ v26.02 已解决（见 12.2）。

## 附录 A：AI 提示词要点

**规划（system）**：你是购物搜索规划器……只输出 JSON；为每个选中的平台生成该平台语言的搜索词（保留品牌与型号原文）；价格必须带币种；不要编造用户没说的条件；`mustNot` 包含用户排除项以及与目标明显冲突的品类（如"手机"目标下的"手机壳"）。

**校验（system）**：你是严格的商品匹配审核员。对每个候选判断与需求的关系：`exact`（品牌型号规格都对上）/ `close`（同款不同配置/颜色/套餐）/ `related`（同品类但不是目标、或二手翻新、或无法确认）/ `mismatch`（配件、不同产品、广告）。给出 0–100 分与 1–2 条中文理由，`flags` 取自 `accessory, used, refurbished, bundle, different_model, ad, price_suspicious, unknown_price`。

**总结（system）**：基于给定结果（不要编造未给出的商品），用中文给出一句话结论、最推荐的一条（引用 id）、价格洞察（最低/中位/平台价差，使用换算后的显示币种）、注意事项（翻新、跨境运费、税）与 2–3 个下一步动作。
